# CLAUDE.md — инструкция для Claude Code по этому репозиторию

Это лендинг курса по допечатной подготовке. Статический сайт, без сборки и бэкенда.
Живой адрес: https://tuptop.github.io/dopechatka/ · Репозиторий: `tuptop/dopechatka`.
Для человека есть [README.md](README.md) и [DEPLOY.md](DEPLOY.md) — эта инструкция их дополняет,
акцент на том, что легко сломать.

## Что это и как устроено

- Корень сайта — папка **`site/`** (её и только её отдаёт GitHub Pages).
- **`site/index.html`** — весь лендинг одной страницей. Вся интерактивность — в одном
  инлайновом `<script>` в конце файла (переключатель звука, плеер видео, чат-бабблы,
  перетаскивание кляксы с ценой, оплата Продамус).
- **`site/style.css`** — все стили. **`site/fonts/`** — шрифт TT Norms. **`site/assets/`** — графика.
- **`site/urok/`** — бесплатный урок (`index.html` + `images/`, собран из Notion-экспорта).
- **`site/success.html` / `fail.html`** — страницы после оплаты.
- Деплой: **пуш в `main` → GitHub Actions (`.github/workflows/pages.yml`)** сам выкладывает `site/`.
  Сборки нет. Проверять локально: `python3 -m http.server 8742 --directory site`.

## Критические правила (нарушение = визуально сломанный сайт)

1. **Фиксированный холст 1440px, без адаптива.** См. раздел «Работа с холстом» ниже — это
   главный источник поломок. Мобильной раскладки нет намеренно (страница масштабируется).
2. **Кэш-бастинг обязателен.** Меняешь `site/style.css` — подними версию в `index.html`:
   `href="style.css?v=NN"` → `NN+1`. Без этого у вернувшихся посетителей останется старый CSS.
3. **Цена дублируется в нескольких местах.** Меняешь цену — синхронно правь: блок `.deal`
   (цены), подвал `.site-footer` (тарифы), аннотацию у программы (`+NNN₽`), объект `PAY.price`
   в `<script>`, и три `<meta ... description>` в `<head>`. Проверь `grep` по старой цифре.
4. **Аудитория курса — дизайнеры и менеджеры, НЕ печатники.** Печатники в проекте — только
   как эксперты («три эксперта», ответы автора и экспертов). Не переписывай позиционирование
   обратно на «курс для печатников».
5. **Шрифт только TT Norms** (лицензия есть), из `site/fonts/`. Не подключай другие.
6. **Кириллица в путях файлов рабочая** (`urok/images/цмик.gif` и т.п.). Имена файлов должны
   ТОЧНО совпадать с `src` в HTML — регистр и «ё» тоже. GitHub Pages отдаёт кириллические URL корректно.
7. **Неразрывные пробелы.** В текстах лендинга много `&nbsp;` (` `) — «в ЦМИК», «1 000 ₽».
   При точечной замене строк матч по обычному пробелу не сработает; матчь точные байты или
   правь структурно.

## Работа с холстом (это то, что ломается чаще всего)

Модель: `#page { width:1440px; margin:0 auto; position:relative }` содержит стопку секций
`<section class="canvas" style="height:NNNpx">`. Секции идут **обычным потоком** (друг под
другом), каждая `position:relative`. Внутри секции контент размещается двумя способами:

- **Абсолютно** — элементы с классом `.abs` (`position:absolute`) и координатами `left/top/
  width/height` в пикселях. Так свёрстана бо́льшая часть (это экспорт из Figma). Координаты —
  относительно своей секции.
- **Потоком** — контейнеры вроде `.program`, `.deal`, `.faq-wrap` (flex/grid/padding).

**Ключевой капкан:** высота секции задана инлайном (`height:NNNpx`) и **абсолютные дети её не
раздвигают**. Если контент внутри стал выше заданной высоты — он вылезет и **наедет на следующую
секцию** (её потоковый сосед просто стоит вплотную снизу).

### Как безопасно менять/добавлять блок

- **Правка текста, цвета, замена картинки того же размера** — безопасно, правь на месте.
  Тронул CSS → подними `?v=` (правило 2).
- **Контент в секции вырос** (добавили строки/описания) — **пересчитай `height` секции**:
  1. Подними локальный сервер, открой страницу.
  2. Померь фактический низ контента и сравни с высотой секции, например:
     ```js
     const s = document.querySelector('section[aria-label="…"]');
     const content = s.querySelector('.program'); // или твой контейнер
     const bottom = content.getBoundingClientRect().bottom - s.getBoundingClientRect().top;
     console.log('низ контента:', Math.round(bottom), 'высота секции:', s.offsetHeight);
     ```
  3. Поставь `height` секции = низ контента + запас (~80–100px). Убедись, что зазор до
     следующей секции положительный.
- **Блок может менять высоту динамически** (аккордеон, раскрывающийся список) — предпочитай
  **потоковую секцию авто-высоты** вместо фикс. пикселей: убери инлайновый `height`, положи
  контент в потоковый контейнер с `padding` (пример — секция «Вопросы»: `.faq` + `.faq-wrap`).
  Тогда раскрытие само раздвигает страницу и толкает соседей вниз, без ручного пересчёта.
- **Новая секция** — вставь `<section class="canvas" style="height:NNN">` в нужное место потока;
  внутри либо `.abs`-элементы (px-координаты), либо потоковый контейнер.

### Проверка перед пушем (обязательно, если менял вёрстку)

- Открой локально, глазами проверь секцию, которую трогал, **и стык со следующей** (нет наезда).
- Меняешь размеры на фикс. холсте — держи ширину контента в пределах 1440 (обычно поля по 120px).
- Тронул CSS → поднял `?v=`.
- Цену/тексты менял в нескольких местах → `grep` по старому значению, чтобы не осталось.

## Как ты (Claude) должен работать здесь

- **Всегда проверяй визуально до пуша.** Подними превью (`python3 -m http.server --directory site`
  или встроенный preview-инструмент), открой затронутое место, при вёрстке сделай скриншот.
- **Деплой = коммит + пуш в `main`.** После пуша GitHub Actions выкладывает ~1 мин; у
  посетителей кэш до ~10 мин.
- **Прежде чем менять позиционирование, тексты офера, цену или структуру секций — подтверди
  с автором.** Мелкие правки (текст, ассеты, багфиксы) — можно сразу.
- **Git identity:** на новой машине один раз задать `git config user.name` / `user.email`.

## Оплата (Продамус)

Объект `PAY` в начале `<script>` в `index.html`: `shop` (поддомен payform), `price` (₽, без
пробелов — держать в синхроне с ценой на странице), `product`, `fallback`. Пока `shop:''` —
кнопки «Оформить предзаказ» ведут в Телеграм. Детали — в [DEPLOY.md](DEPLOY.md).
